Measures of Central Tendency

Three Ways to Say “Typical”

Measure Meaning
Mean the average
Median the halfway point
Mode the most frequently occurring value

Measures of central tendency summarize a vector of data by locating the typical, the middle, or the most common point.

Practice — The Mean

rainfall <- c(0, 0, 0, 2, 1, 1, 4)   # rain each day this week

# The hard way:
sum(rainfall) / length(rainfall)
[1] 1.142857
# The easy way:
mean(rainfall)
[1] 1.142857

Practice — The Median

rainfall
[1] 0 0 0 2 1 1 4
sort(rainfall)   # middle value of the sorted data?
[1] 0 0 0 1 1 2 4
median(rainfall)
[1] 1

Practice — The Mode

rainfall          # which value appears most often?
[1] 0 0 0 2 1 1 4
library(modeest)  # install.packages("modeest") once, library() every session
mfv(rainfall)     # mfv = "most frequent value"
[1] 0

What Do These Look Like?

stats <- tibble(
  measure = c("Mean", "Median", "Mode"),
  value = c(mean(rainfall), median(rainfall), mfv(rainfall))
)
ggplot(tibble(rainfall), aes(rainfall)) +
  geom_histogram(binwidth = 1, fill = "lightblue", color = "black") +
  geom_vline(data = stats, aes(xintercept = value, color = measure),
             linewidth = 1.2, linetype = "dashed") +
  labs(title = "Rainfall with Mean, Median, and Mode",
       x = "Rainfall (inches)", y = "Frequency", color = NULL)

Why We Care in CJ: Sentencing

# Sentence lengths for 10 people convicted of robbery (years)
sentences <- c(2, 2, 3, 3, 3, 4, 4, 5, 5, 30)   # note the outlier!

mean(sentences)
[1] 6.1
median(sentences)
[1] 3.5
mfv(sentences)
[1] 3

One 30-year sentence drags the mean to 6.1 — nobody in the data actually got a “typical” 6-year sentence.

Why We Care in CJ: Sentencing

Thoughts?

  • Why do these three values (mean = 6.1, median = 3.5, mode = 3) give such different impressions of “typical” sentence length?
  • Which one might be most fair to use when describing a sentencing policy to the public?
  • When might the mean be misleading?

The Same Thing in Real Data

Community-level crime rates in Chicago, 2025:

areas |>
  summarize(
    mean_rate   = mean(crime_rate),
    median_rate = median(crime_rate),
    max_rate    = max(crime_rate)
  )
# A tibble: 1 × 3
  mean_rate median_rate max_rate
      <dbl>       <dbl>    <dbl>
1      96.9          82     292.

Who’s Dragging the Mean?

areas |> slice_max(crime_rate, n = 3) |> select(community, crime_rate)
# A tibble: 3 × 2
  community          crime_rate
  <chr>                   <dbl>
1 Fuller Park              292.

3 Englewood                214.

The Loop’s rate (driven by a small residential population and huge daytime crowds) pulls the mean above the median — same lesson as the 30-year sentence, in live data.

Measures of Dispersion

Central Tendency Isn’t the Whole Story

Three people run for city council; only the top two vote-getters win:

Scenario 1

  • A = 200 votes
  • B = 300 votes
  • C = 400 votes

Scenario 2

  • X = 299 votes
  • Y = 300 votes
  • Z = 301 votes

In both cases the average is 300. But scenario 1 has much greater spread in support; scenario 2 is tightly clustered — it’s hard to say who’s truly “preferred.”

→ We need measures of dispersion: range, deviations, variance, standard deviation.

Practice — Range

votes1 <- c(200, 300, 400)   # wide spread
votes2 <- c(299, 300, 301)   # tight cluster

mean(votes1); mean(votes2)   # identical means
[1] 300
[1] 300
range(votes1); diff(range(votes1))
[1] 200 400
[1] 200
range(votes2); diff(range(votes2))
[1] 299 301
[1] 2

Practice — Deviations from the Mean

votes1 - mean(votes1)
[1] -100    0  100
votes2 - mean(votes2)
[1] -1  0  1

Why can’t we just sum the deviations?

sum(votes1 - mean(votes1))   # they always cancel to zero!
[1] 0

Practice — Sum of Squares

Squaring makes every deviation positive (and emphasizes big misses):

sum((votes1 - mean(votes1))^2)
[1] 20000
sum((votes2 - mean(votes2))^2)
[1] 2

Practice — Variance and SD

# Variance = mean squared deviation (population formula)
sum((votes1 - mean(votes1))^2) / length(votes1)
[1] 6666.667
# Standard deviation = square root of variance (back to vote units!)
sqrt(sum((votes1 - mean(votes1))^2) / length(votes1))
[1] 81.64966
var(votes1); sd(votes1)   # R's built-ins use the SAMPLE formula (divide by n-1)
[1] 10000
[1] 100
var(votes2); sd(votes2)   # more on WHY in Session 4
[1] 1
[1] 1

Seeing the Machinery

Standard Deviation, in Words

The standard deviation measures how spread out the data are around the mean.

“On average, how far is each value from the mean?”

We square the deviations (to make them positive and emphasize larger differences), average them (that’s the variance), then take the square root (back to the original units).

Why the Standard Deviation?

  • Same units as the data — variance is in squared units; SD is interpretable
  • Works with the normal distribution — SD tells us how typical or extreme a value is
  • The basis for many tools — confidence intervals, hypothesis tests, z-scores, regression all rely on it
  • Lets you compare variability across datasets with similar scales

In CJ Scenarios

Response times for patrol officers:

  • Low SD → officers respond in consistently similar times
  • High SD → sometimes fast, sometimes slow — inconsistency that matters for policy, supervision, training

Sentence lengths for the same crime:

  • High SD might suggest inconsistency — or bias — in sentencing

Real Data: Consistency Across Communities

# Violent-crime rates: how much do Chicago communities differ?
areas |>
  summarize(
    mean_violent = mean(violent_rate),
    sd_violent   = sd(violent_rate),
    min_violent  = min(violent_rate),
    max_violent  = max(violent_rate)
  )
# A tibble: 1 × 4
  mean_violent sd_violent min_violent max_violent
         <dbl>      <dbl>       <dbl>       <dbl>
1         30.7       22.5           4        111.

The SD is nearly as large as the mean — Chicago communities differ enormously in violence exposure. That inequality is a finding, and it took exactly one line of dispersion statistics to see it.

Distributions

What Is a Distribution?

A distribution shows how many observations fall at different values — the shape of the data.

It answers:

  • “Where do most of the values fall?”
  • “How spread out are they?”
  • “Are some values rare or common?”

We visualize distributions with a histogram.

The Normal Distribution

sims <- tibble(x = rnorm(n = 1000, mean = 100, sd = 10))
ggplot(sims, aes(x)) + geom_histogram(bins = 30, fill = "grey80", color = "white")

Symmetrical, bell-shaped; defined by two numbers — the mean (center) and SD (spread). Try different values!

SD and the Normal: the Empirical Rule

pct_within <- function(k) 100 * (pnorm(k) - pnorm(-k))
tibble(k = 1:3, pct_within = round(pct_within(1:3), 2))
# A tibble: 3 × 2
      k pct_within
  <int>      <dbl>
1     1       68.3
2     2       95.4
3     3       99.7

The Poisson Distribution

pois_sims <- tibble(x = rpois(n = 1000, lambda = 1))
ggplot(pois_sims, aes(x)) + geom_bar(fill = crju_colors["navy"])

Often skewed, especially when λ is low. Models counts of rare events: 911 calls per hour, crimes per day, cars per minute. One parameter: λ = expected number of events. Try different values!

The Poisson Is Not Hypothetical

Daily robbery counts in our Chicago sample, all of 2025:

daily_robberies <- crimes |>
  filter(primary_type == "ROBBERY") |>
  count(date)

ggplot(daily_robberies, aes(n)) +
  geom_bar(fill = crju_colors["garnet"]) +
  labs(x = "Robberies per day", y = "Number of days",
       title = "Real crime counts look Poisson")

Why We Care About Distributions in CJ

  • The normal distribution helps us understand common variation (response times, test scores)
  • The Poisson distribution models event counts, especially rare ones — crimes, incidents — and underlies many forecasting tools
  • Recognizing the shape of your data is the first step in choosing the right analysis — a theme for the whole semester
