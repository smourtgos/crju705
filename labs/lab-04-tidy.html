Lab 4 · Tidy Data: Pivoting Longer and Wider

CRJU 705 · Session 4

Goal: learn to reshape data between wide and long form with pivot_longer() and pivot_wider(), and pick up the workflow habits that keep your analyses reproducible. This lab assumes you’ve read R4DS Ch. 5 (Data tidying) and Ch. 6 (Workflow: scripts and projects).

How labs work: run the Setup chunk as-is, follow the Walkthrough along with me, then complete the Your Turn tasks in your own script. The Exit Ticket gets submitted to Canvas before you leave.

Setup

Open RStudio, start a new R script, and run:

library(tidyverse)

cities  <- read_csv("https://smourtgos.github.io/crju705/data/cities-wide.csv")
reentry <- read_csv("https://smourtgos.github.io/crju705/data/reentry-wide.csv")

cities holds 100 cities (simulated, but realistic): a few city characteristics plus violent crime rates for 2015–2025. reentry holds 150 reentry-program participants with a monthly employment indicator (1 = employed that month) for their first 12 months after release. Walkthrough

What’s wrong with this data?

Nothing — for a spreadsheet. cities is wide: each year’s violent crime rate lives in its own column (vcr_2015 … vcr_2025). That’s fine for eyeballing, but notice what it breaks in R:

  • You can’t put year on the x-axis of a ggplot — there is no year variable. Year is data, but it’s trapped in the column names.
  • You can’t summarize() an average rate per year, or filter to years after 2020, for the same reason.

R4DS’s tidy-data rules: every variable is a column, every observation is a row. Here one observation is really “a city in a year” — so tidy form needs 100 × 11 = 1,100 rows, not 100.

pivot_longer() — column names become data

cities_long <- cities |>
  pivot_longer(
    cols = starts_with("vcr_"),   # which columns to gather
    names_to = "year",            # where their NAMES go
    values_to = "violent_rate"    # where their VALUES go
  )

1,100 rows — one per city-year. But look at year: it’s the text "vcr_2015", not a number. parse_number() strips the text and keeps the digits:

cities_long <- cities_long |>
  mutate(year = parse_number(year))

Notice the story hiding in there — rates climb into 2020–2021, then fall. And a line plot over time, impossible ten minutes ago, is now routine:

cities_long |>
  summarize(mean_rate = mean(violent_rate), .by = c(region, year)) |>
  ggplot(aes(x = year, y = mean_rate, color = region)) +
  geom_line(linewidth = 1) +
  labs(title = "Violent crime rate by region, 2015-2025",
       x = NULL, y = "Mean violent crimes per 100k", color = "Region")

pivot_wider() — and back again

Sometimes you want wide (for a table in a report, or to compute 2025 minus 2015):

cities_long |>
  pivot_wider(
    names_from = year,
    values_from = violent_rate,
    names_prefix = "vcr_"
  ) |>
  select(city, region, vcr_2015, vcr_2025) |>
  mutate(change = vcr_2025 - vcr_2015)

Workflow hygiene: scripts and projects

Three habits from R4DS Ch. 6 that I will hold you to all semester:

  1. Everything in a script, nothing only in the console. The console is for experimenting; the script is the record. If it matters, it’s in the script.
  2. Use an RStudio Project for this course. File > New Project… once, then always open the course via the .Rproj file. Your working directory is then always the project folder, paths stay relative, and your code runs on any machine — including mine when I grade it.
  3. Never rely on the Environment pane. Objects in memory are disposable; your script + your data are the source of truth. Prove it to yourself right now: Session > Restart R, then re-run your script top to bottom. If it doesn’t reproduce everything, fix the script — you just saved a future you from a very bad day. (I also recommend Tools > Global Options > un-check “Restore .RData into workspace at startup.”)
