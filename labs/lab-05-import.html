Lab 5 · Importing Real Data

CRJU 705 · Session 5

Goal: get real data into R correctly — from a CSV on the web and from a messier Excel file — and know what to do when the import goes sideways. This lab assumes you’ve read R4DS Ch. 7 (Data import) and Ch. 8 (Workflow: getting help).

How labs work: run the Setup chunk as-is, follow the Walkthrough along with me, then complete the Your Turn tasks in your own script. The Exit Ticket gets submitted to Canvas before you leave.

Setup

Open RStudio, start a new R script, and run:

library(tidyverse)
library(readxl)

crashes <- read_csv("https://smourtgos.github.io/crju705/data/crash-ak.csv")

Walkthrough

What did read_csv() decide for us?

read_csv() guessed a type for every column. See its guesses with spec():

spec(crashes)
cols(
  incident_id = col_character(),
  date = col_character(),
  time = col_time(format = ""),
  county = col_character(),
  latitude = col_double(),
  longitude = col_double(),
  num_vehicles = col_double(),
  occupants = col_double(),
  primary_cause = col_character(),
  secondary_cause = col_character(),
  severity = col_double(),
  injuries = col_double(),
  fatalities = col_double(),
  road_condition = col_character(),
  driver_age = col_double(),
  driver_gender = col_character(),
  intox_alcohol = col_double(),
  intox_drugs = col_double(),
  intox_any = col_double(),
  vehicle1_make = col_character(),
  vehicle1_model = col_character(),
  vehicle1_year = col_double(),
  vehicle2_make = col_character(),
  vehicle2_model = col_character(),
  vehicle2_year = col_double()
)

Mostly sensible — but look at date: it’s col_character(). The file stores dates as "02/20/2023" (MM/DD/YYYY), and readr only auto-detects ISO-style dates (2023-02-20). Right now R thinks our dates are just text — you can’t sort them chronologically, subtract them, or extract a year.

The lesson: never assume the import worked. Check the types.

Telling read_csv() what you want: col_types

You can hand read_csv() an explicit specification instead of letting it guess. What happens if we naively declare date a date column?

crashes_bad <- read_csv(
  "https://smourtgos.github.io/crju705/data/crash-ak.csv",
  col_types = cols(date = col_date())
)
Warning: One or more parsing issues, call `problems()` on your data frame for details,
e.g.:
  dat <- vroom(...)
  problems(dat)

readr warns us — and problems() shows exactly what went wrong, row by row:

problems(crashes_bad)

Every row “failed to parse”: col_date() expected ISO format and got "02/20/2023", so the whole column became NA. Two fixes:

Fix 1 — tell readr the format up front:

crashes_fixed <- read_csv(
  "https://smourtgos.github.io/crju705/data/crash-ak.csv",
  col_types = cols(date = col_date(format = "%m/%d/%Y"))
)
crashes_fixed |> select(incident_id, date) |> head(3)
# A tibble: 3 × 2
  incident_id date      
  <chr>       <date>    
1 AK340354    2023-02-20
2 AK991668    2023-04-09
3 AK050345    2022-06-29

Fix 2 — import as text, then parse with lubridate. This is my everyday habit, because lubridate’s helpers are nearly unbreakable: name the function after the order of the components — mdy() for month/day/year, dmy() for day/month/year, ymd() for year/month/day:

crashes <- crashes |>
  mutate(date = mdy(date))

crashes |> select(incident_id, date, time) |> head(3)
# A tibble: 3 × 3
  incident_id date       time    
  <chr>       <date>     <time>  
1 AK340354    2023-02-20 02:12:34
2 AK991668    2023-04-09 17:56:02
3 AK050345    2022-06-29 17:36:39

Now date is a real date. Real dates unlock real questions:

crashes |>
  mutate(year = year(date)) |>
  count(year)
# A tibble: 5 × 2
   year     n
  <dbl> <int>
1  2022  4960
2  2023  4972
3  2024  5064

Always confirm a date parse did what you think: check sum(is.na(...)) after parsing. Zero new NAs means every value parsed.

sum(is.na(crashes$date))
[1] 0

names(crashes)

These are already clean: lowercase, no spaces, words separated by underscores — so you never need backticks. When you import data from the wild, look for the troublemakers: spaces (Driver Age), capitals, punctuation (Injuries?), or the dead giveaway ...1 — readr/readxl’s placeholder name for a column with no header at all. You’re about to meet one.

Same 20,000 crashes, but three problems the CSV didn’t have:

  1. A junk first column named ...1 — someone saved the spreadsheet with Excel’s row numbers included, and there’s no header for them.
  2. date and time imported as datetimes. Excel stores everything as datetimes under the hood; note time’s absurd 1899-12-31 dates — that’s Excel’s “time only” anchor leaking through.
  3. vehicle2_year imported as character. Why? Single-vehicle crashes have no second vehicle, and this spreadsheet recorded those cells as the literal text "NA" — which readxl treats as a word, not as missing:
crashes_xl |> count(vehicle2_year == "NA")
# A tibble: 2 × 2
  `vehicle2_year == "NA"`     n
  <lgl>                   <int>
1 FALSE                   15981
2 TRUE                     4019

Fix all three — tell read_excel() what “missing” looks like, drop the junk column, and flatten the datetimes:

crashes_xl <- read_excel("crash-ak.xlsx", na = c("", "NA"))
crashes_xl <- crashes_xl |>
  select(-`...1`) |>
  mutate(
    date = as_date(date),      # drop the meaningless midnight timestamp
    hour = hour(time)          # keep the useful part of the time column
  )

crashes_xl |> select(incident_id, date, hour, vehicle2_year) |> head(3)
# A tibble: 3 × 4
  incident_id date        hour vehicle2_year
  <chr>       <date>     <int>         <dbl>
1 AK340354    2023-02-20     2          2007
2 AK991668    2023-04-09    17          2011
3 AK050345    2022-06-29    17          2011

vehicle2_year is now numeric with honest NAs — because na = c("", "NA") told readxl both blank cells and the text "NA" mean missing. This distinction — the two-letter word “NA” versus a genuinely empty value — causes an astonishing share of real-world data misery.

Save your clean version

Once the cleaning works, write the result out so you (and collaborators) never have to repeat it. Keep the raw file untouched and give the clean one its own name:

write_csv(crashes, "crash-ak-clean.csv")

write_csv() stores dates in ISO format (2023-02-20), so the next read_csv() parses them automatically — your future self imports with zero fixes.

When R yells at you: getting help

You will spend more time reading error messages than reading textbooks. A system:

1. Actually read the message. Modern tidyverse errors usually tell you the fix:

crashes |> filter(county = "Anchorage")
Error in `filter()`:
! We detected a named input.
ℹ This usually means that you've used `=` instead of `==`.
ℹ Did you mean `county == "Anchorage"`?

The error names the problem and the solution. Slow down and read before you panic.

2. Read the help page. ?read_csv — skim Usage and Arguments, then jump to the Examples at the bottom, which are runnable.

3. Make a reprex (a reproducible example) before asking anyone for help: the smallest self-contained chunk of code + data that produces your error. Half the time, building the reprex reveals the bug yourself; the other half, it lets a helper answer in minutes. A question like “my import is broken” is unanswerable; “read_csv() turns my date column into NA — here are three sample rows and my code” gets solved.

4. Search the exact error text (in quotes). Someone has hit it before you.
